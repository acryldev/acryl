The Blends frame: the app is the product, the frame is a workbench

Every app made with ACRYL Blends is shown inside a frame while it is being built. This mockup tests the frame against the 80/20 worry: the frame may only hold what every builder of every kind of app needs, and it disappears for the people the app is for.

Where each thing goes, and why

You read left to right. Left is history and context, the centre is the thing itself, and right is the action on it. That's also where ACRYL already puts them, so people coming from ACRYL find them where they expect.

PlaceHoldsThe question it answersDefault
Centre canvasThe app, full size. The app's own panels, top bar and bottom bar live inside the canvas and never touch the frame's panels."What does my app look like and do right now?"Always shown, the largest area
Right panelEverything you work with, as tabs opened with +. Agents: the chat (DSH chat mode with your model), and Claude, Codex or Pi run as they are, TUIs in a PTY, never rebuilt as chats. They are the app's drivers: skills teach them the ACRYL app, they extend it with Cordis plugins and use its UI through acryl-control. Tools: a terminal, Files (fuzzy search over every file, ⌘P; a file opens as its own tab, with syntax highlighting) and Git (changes and history). The chat has a History button at its top left that lists every chat, closed ones included, and opens a pick as a tab. The tab strip with + moves here from ACRYL's centre. There is no Browser tab, because the canvas is the browser."Change this for me" and "Let me look under the hood"Open on first run, then remembered
Left panelAs in the ACRYL IDE: the project's git branches (main, feature-…). Expanding a branch shows what is open on it: chats, agent sessions and PTYs, never files or other secondary tabs. Clicking an item opens it in the right panel. Below: Versions of the selected branch (save points: go back, keep, share through git or the Blend registry), and Feedback from users when it is on."Which line of work am I on, and what is running there? Take me back to the version that worked. What do users say?"Open on first run, then remembered
SettingsGeneral (with a short list of shortcuts), Models (keys and sign-in), Agents, Plugins (a Blend is plugins), Support."Set up my model and agents once"A dialog from the gear

Modes

The frame belongs to the builder, so the mode decides whether it exists at all. Production is not a theme of the frame; it is the app with no frame.

Build agreed

The frame: branches and versions, the canvas, agents and tools. Only the app's owner reaches it (the owner-only frame token).

Preview agreed

A Build / Preview switch in the top bar hides the frame, so you see exactly what users will see, on the same running app. A small pill brings you back. Nothing restarts.

Production agreed

The published app with no frame and no editing: no panels, no agent, no Settings. Today's ACRYL_PRODUCTION_KEEP switch already turns the agent off; the frame goes off with it.

Production + assistant your idea, power-user mode

Only the agent panel is exposed. The assistant drives the app's UI through acryl-control: opens pages and panels, filters, fills in the app's own forms, helps people find things. It is refused anything that changes the app, its code, its plugins or its secrets, so a prompt injection can at most click what the user could click.

Production + feedback agreed, opt-in plugin

Pressing Feedback turns the pinpoint picker on: the user clicks the exact element where they hit a problem or had an idea, or chooses "Nothing specific" for general feedback, then writes the note. Notes land in the builder's left panel; one click hands a note to an agent as a task, with the page, the element's selector and a screenshot attached.

Other modes worth considering later, not proposed now: Share preview (a link to one version for a client to try and comment on, before it goes live) and Demo (Production with seeded sample data, for a workshop or a sales call).

One frame for every app

No special UX per kind of app. Every Blends app, a shop, a todo board or a coding tool, gets the same left panel and the same right panel with the same contents. We take from the ACRYL IDE only what building an app needs, and drop what only an IDE needs.

Kept, as right-panel tabs agreed

Agents and PTYs (Claude, Codex, Pi, terminal). Files: the tree, and a file opens as a tab. Git: changes and history, push and pull.

Kept, in the left panel agreed

Sessions, and Versions under them: the everyday face of git.

Dropped: IDE review views

Review, Checks, Comments, and the separate Changes page (Git's tab shows the changes).

Dropped: branches and worktrees

The branch/worktree tree, the branch tab and the git status bar. Versions and the Git tab cover what an app builder needs.

Dropped: a separate terminal dock

Terminals are tabs in the right panel, next to the agents.

Dropped: IDE Settings sections

Tabs, Command palette, Shortcuts, Built-in plugins. A short shortcuts list goes into General.

The ratio: default view is about 100% app. While working with an agent it is about 65% app and 35% agent. For the people the app is for, it is 100% app, always.

What happens next

The redesign becomes one acrylblends branch (125), built as Cordis plugins on the frame that 119, 122 and 123 put on main, in four slices: (1) the right panel: the tab strip with +, the chat with its History button, PTY agents as they are, terminal, Files with fuzzy search and highlighted file tabs, Git; the centre canvas holds only the app; (2) the left panel: branches with their open items, Versions, the Build / Preview switch, and dropping the IDE-only parts; (3) Settings → Plugins, the plugin navigator; (4) the production modes: feedback with the pinpoint picker, and the assistant that drives the UI through acryl-control without changing the app. The visual reference screenshots come after slice 2.
