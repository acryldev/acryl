ACRYL AOS: a computer whose apps are agents' tools

AOS (agentic in-app operating system) is a new face for ACRYL Control Center. It is a whole computer in one window: a desktop, a dock, app windows, and one chat that works across every app. Every app is a Blend, and every Blend gives the agent deterministic tools. The agent plans with the model and then acts with tools, so the work it repeats costs no model tokens. All apps share one runtime, one host process and one package store, so an extra app costs megabytes, not 700 MB.

"maybe we can turn acryl control center (gui, web and tui) into like an "Operating System App" where we see "apps icons" inside ... simulating "OS" inside of Acryl CC" (owner, 2026-11-23)

"like we design a "computer" (OS-simulation) with own agentic apps / deterministic tools save tokens as they are doing stuff deterministic" (owner, 2026-11-24)

Inspiration: Vesence's "agent-native computer" (vesence.com/platform), where files, mail and calendar sit in one workspace with one chat. AOS takes that idea and applies it to apps people and agents make. The apps are open Blends, each one a set of Cordis plugins with typed tools. AOS runs on your machine and, in the browser, on WebBoxes.ai.

Try it

Click an icon to open it, and drag windows by their bar. Right-click an icon (or long-press it) for its actions. Ask the chat something. The suggestions run a real-looking flow: the model plans, the tools act, and "Save as workflow" replays the same run without the model. How one computer runs many apps

An app brings only its own code. Everything below it is shared and exists once per version.

Deterministic tools save tokens

An app's tool returns a typed result, such as "these 3 contacts" or "row 14 added". The model never re-reads the screen or works the answer out again. It spends tokens only to plan and to write. A run made of tools can be saved as a workflow (the Workflow Automation Blend), and then it runs again with no model at all.

One runtime, one host, one store

Today every app carries its own Electron and framework (701 MB measured, below). In AOS, one Electron main process draws every window, sharing its GPU and network processes. One Node host runs every app as a Cordis scope, and the store holds each package version once. Apps nobody is using go to sleep (D10).

Still a real app outside

Any app can step out of AOS. "Add to Applications" writes a launcher that Spotlight, the Start menu or the app menu finds (D4), and "Export as installer" makes a DMG, exe or deb (D6). Inside AOS, a window can pop out into a real OS window.

Risks

One crash, many apps

A shared host means a hung or crashing app can take the others with it. Answer: trust groups (decision 1). Each group's host is watched and restarted, and only that group's apps reopen.

Versions that differ

An app built on another Blends version, or with a conflicting package major (the zod 3 over zod 4 case found on WebBoxes, +278 MB), cannot share. It gets its own host and store layer, and the Activity app says so.

Tools must stay deterministic

A workflow replays only what its tools did. A tool that reads the clock, the network or a random number has to declare that, and the replay asks you before it repeats anything that sends or deletes.
