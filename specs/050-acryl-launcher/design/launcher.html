The ACRYL launcher: nothing to memorize

One list of things a person can do with ACRYL, offered step by step. The same steps in the terminal (npx acryl) and in a desktop app you download as one file. Every step runs a command that already exists, and shows that command at the end.

"user interactively just is offered step by step interaction to choose what to do instead of memorizing commands ... users just download this binary exe/deb/DMG and nothing more ... or they run single npm command to invoke TUI mode" (owner, 2026-11-12)

Why

Today a person needs the commands; with the launcher they need one

Today: six commands from the guide

npm create acrylblends@latest my-app agent -- --desktop
cd my-app && npm install
npm run dev            # or: npm run desktop
npm run acryl -- plugin pull github:ana/clock@1.0.0@sha256:…
npx acrylblends upgrade
npx acrylblends open   # the address again

The Sentry talk (2026-11-11): "it looked complicated to the audience".

With the launcher: one command, or one download

npx acryl
  ❯ Create an app      Enter
    Starter: Blank     Enter
    Name: my-app       Enter   → the app opens in the frame

Or download ACRYL (DMG, EXE, DEB), open it, press Create an app. No Node, npm or terminal.

What the launcher offers

Nine things to do, each ending with the command that does it

Create an app

Blank, a starter (notes, chat, todo, agent) or a Blend from the registry; opens in the frame.

acryl new my-app notes

Open an app

Your apps in ~/.acryl/apps, in the browser or its own window.

cd my-app && npm run dev

Install a Blend

Pick from the registry (CRM, notes, the ACRYL IDE as acryl.code).

acryl install acryl.crm (new)

Pull a plugin

From a person's GitHub or the plugin registry, digest checked, into a chosen app.

acryl plugin pull github:ana/clock

Share a plugin

Publish one of your app's plugins so others can pull it.

acryl plugin publish clock

Set up a model

DeepSeek key, Claude or ChatGPT sign-in; kept in the app's own store.

(Settings › Models)

Update

ACRYL itself, or an app to the current release, with a preview first.

acryl update

Check this machine

Node, git, ports, disk; each problem with its fix.

acryl blends preflight

Open ACRYL Code

The IDE, which is one Blend (049 D9).

acryl code
The two faces, one flow

"Create an app", step by step, in the terminal and on the desktop

Pick a step; both faces show the same step. Arrows and Enter in the terminal, clicks on the desktop. Esc goes back, nothing runs before the confirm step.

Terminal · npx acryl
ACRYL

Terminal face: @earendil-works/pi-tui and acryl-ui-tui, which the ACRYL CLI already uses. Desktop face: @acryl/ui. Both libraries implement one component contract (plugins/acryl-ui/contracts/components.json: Card, SelectField, RadioGroup, Input, SecretField, Progress, Alert …), so a step is drawn with the same component on both.

How it is built

One service holds the steps; the faces only draw them

Clean Architecture

The dependency rule: steps and their state live in the runtime service; a face holds no step, rule or command line.

Philosophy of Software Design

A deep module: four calls and events for every face; spawning, npm, registries and keys stay behind it.

DDD Distilled

The screen speaks the product's words: app, Blend, plugin, model. Never profile, row or fiber.

Pragmatic Programmer

DRY: the command shown at the end comes from the same data that runs the step, so it can't drift.

Risk: two places for one rule

If a face starts building command lines, the faces drift apart. Guard: a test fails when a face file spawns a process.

Risk: download size

The desktop file carries Electron and Node (the ACRYL Desktop DMG today is about 0.7 GB installed). A launcher-only build can be far smaller if the frame is fetched on first create.

Risk: acryl changes meaning

Today bare acryl starts the IDE's terminal client. Question 1 decides; scripts keep working because a pipe never gets the launcher.
