ACRYL Durable: one running app, the whole team inside it

A Blend runs in a WebBoxes.ai box and keeps running when every window is closed. Anyone signed in to the app can attach from the desktop, the web, the CLI or Telegram and sees the same live state. A crash or a restart resumes where it was.

Modeled on Pi Durable (MIT, earendil-works/pi, packages/durable): every step written down before and after it runs, tools that say whether they are safe to repeat, tasks that wait with no process running, versioned documents sent as small patches.

How it works

Every step is written down twice

flowchart LR I["Write the intent"] --> E["Run the step"] E --> R["Write the result"] R --> A["Move to the next step"] E -. crash .-> C{"Safe to repeat?"} C -- yes --> E C -- no --> Q["Ask the owner"]

Persistent objects

The app's data are versioned JSON documents. A change is a small patch: stored, so you can rewind, and sent to everyone attached, so screens update at once.

One id per message

A message sent twice, from a retry or two devices, is handled once.

One Cordis service

A durable service with storage providers (a file, the box volume, later a database). No second runtime next to Cordis.
