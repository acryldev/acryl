## Objective

Stand up a first-party ACRYL plugin marketplace that any DSH Desktop user can
connect to - not only ACRYL Desktop. It has two halves:

1. **Catalog service** - a hosted, provider-neutral HTTPS JSON catalog at
   `acryl.dev` that conforms to the `dsh-community-market` `catalog-source`
   contract, so it is selectable from any market client that supports custom
   sources.
2. **Market client distribution** - publish the ACRYL market client
   (`dsh-community-market`, or a slimmed `acryl-market`) to npm so a plain DSH
   Desktop user can `dsh plugin add` it and get the ACRYL catalog
   pre-registered, with the same UI ACRYL Desktop ships built in.

The marketplace must not introduce a parallel plugin runtime, install engine,
or trust model. It reuses the existing `dsh-community-market` contracts,
adapters, and managed-install verification.

## Source of truth

The catalog contract is already defined and generated in-repo. The service
must project exactly these shapes, no extensions:

- `CatalogSourceManifest` v1.0.0
  (`dsh-community-market/src/contracts/generated/catalog-source.ts`) -
  the user-registered manifest URL.
- `CatalogProviderPage` v1.0.0
  (`.../generated/catalog-provider-page.ts`) - the `/v1/plugins` response.
- Identity normalization and managed-install verification in
  `dsh-community-market/src/contracts/identity.ts` and
  `.../install/service.ts` stay authoritative. The service publishes data;
  the client verifies npm identity, canonical repository, integrity, absence
  of lifecycle scripts, and DSH bundle evidence at install time.

Local, user-owned state (which sources are registered, which are enabled)
stays on the device. The service is stateless catalog data only.

## Current state (see research.md)

- `dsh-community-market` already implements the full client: source store,
  `standard-http` / `dsh-1024store` / `dshfind` adapters, Market UI, managed
  install, schemas. It is an optional Desktop Market provider, disabled by
  default, `private: true`.
- `acryl.dev` (`acryldev/acryldev.github.io`) already serves
  `public/v1/plugins` in `CatalogProviderPage` shape, generated by
  `scripts/sync-acryl-catalog.mjs` from npm keyword `acryl-package` discovery
  plus a maintained list.
- No `CatalogSourceManifest` is published yet.
- The `standard-http` adapter requires the manifest URL and the `/v1/plugins`
  endpoint to share one origin, over credential-free HTTPS on port 443, no
  query or fragment on the endpoint.

## Deliverables

### A. Catalog service at acryl.dev

- Publish a `CatalogSourceManifest` at a stable path, e.g.
  `https://acryl.dev/.well-known/dsh-catalog.json`:
  - `providerId: dev.acryl.catalog`
  - `name: "ACRYL Plugin Marketplace"`
  - `attribution: { name: "ACRYL", url: "https://acryl.dev" }`
  - `transport: { kind: https-json, endpoint: "https://acryl.dev/v1/plugins", method: GET }`
  - `query.supported`: start with `[q, category, cursor, limit]`; declare
    `defaultLimit` / `maxLimit` honestly for what the endpoint actually does.
- Make `/v1/plugins` schema-conformant:
  - add the required `page` object (`CatalogProviderPage.page`)
  - decide the query story on a static host (GitHub Pages cannot read query
    params server-side). Options, to be chosen in `plan.md`:
    1. Serve one full page (all first-party plugins), let the client filter
       and declare `query.supported: []` beyond paging.
    2. Move `acryl.dev` catalog routes to a small edge function
       (Netlify/Cloudflare/Vercel) that honors `q/category/cursor/limit`.
    3. Pre-render sharded pages keyed by cursor.
  - keep `generateGeneratedAt` / `revision` populated for cache validation.
- Add a manifest + endpoint conformance test to the acryl.dev repo that
  validates the served JSON against the in-repo generated schema (import or
  vendor `parseCatalogSource` / `parseCatalogProviderPage`).

### B. Default source registration

- ACRYL Desktop: register the acryl.dev manifest as a built-in source in the
  `community-market` provider so it appears without the user adding a URL.
  Built-in sources stay removable; user-added sources are unaffected.
- The `dsh-1024store` built-in source stays as-is; ACRYL is added alongside,
  not as a replacement.

### C. Market client on npm (for non-ACRYL DSH Desktop)

- Decide: publish `dsh-community-market` as-is (drop `private: true`) or cut a
  slimmed `acryl-market` package. Recommendation: publish `dsh-community-market`
  unscoped or as `@acryl/market`, since it already uses only stock DSH/Cordis,
  profile, and Desktop service contracts (repo rule in root `CLAUDE.md`).
- The published client ships with the acryl.dev manifest pre-registered.
- Declare peer-dependency ranges against DSH packages deliberately and
  maintain a compatibility matrix. This is the exact failure mode that broke
  `dshmarket` (built against one `@deepseek-ai/dsh-settings`, hard-broke on
  `0.1.5-alpha.1` when `installSettingsSection` was removed). Runtime imports
  from DSH packages must be treated as a versioned contract, and the client
  must fail soft (surface a notice, stay disabled) rather than take down the
  plugin host - see spec 031 / the market-provider import guard.
- List it in `acryl.dev/store` and `acryl.dev/packages` featured, and in the
  awesome-dsh catalog, same as `cordis-plugin-graph`.

### D. Documentation

- `docs/acryl/marketplace.md` - the catalog contract, how to run your own
  compatible catalog, how a third party gets listed, the trust model.
- A short "add the ACRYL marketplace" guide for stock DSH Desktop users.

## User experience

- **ACRYL Desktop**: Settings -> Plugins -> Plugin market tab (already exists
  when the `community-market` provider is enabled). The ACRYL source is
  present by default. Browse, search by category/capability, install with
  managed verification.
- **Stock DSH Desktop, our client**: `dsh plugin add <acryl-market pkg>`,
  restart, Plugin market tab appears with the ACRYL source registered.
- **Stock DSH Desktop, another client that supports custom sources**: user
  pastes `https://acryl.dev/.well-known/dsh-catalog.json` as a source URL.
- No terminal is required for the browse/install flow itself in any of these;
  terminal is only the one-time client install for the non-ACRYL case.

## Security and trust

- Manifest and endpoint must be same-origin, credential-free HTTPS:443, no
  query/fragment on the endpoint - enforced by `assertStandardSourceTrustRoot`.
- The service never influences install safety: the client independently
  verifies every package against npm (identity, canonical repository,
  integrity, no lifecycle scripts, DSH bundle evidence) before install.
- Catalog JSON is untrusted input on the client - already parsed through the
  bounded generated schema. The service side must not echo unvalidated
  third-party submission text into the page without the same bounds.
- Listing a third-party plugin in the ACRYL catalog is not an endorsement of
  its code; the catalog entry carries `publisher` and `repository` for the
  user to judge, same as npm.

## Out of scope

- Payments, private/paid plugins, license enforcement.
- A submission portal or review queue (v1 is a maintained list + npm keyword
  discovery, same as the current acryl.dev catalog generator).
- Hosting plugin tarballs - install stays through npm.
- Replacing or patching the third-party `dshmarket` client.

## Acceptance criteria

- `https://acryl.dev/.well-known/dsh-catalog.json` validates against
  `CatalogSourceManifest` v1.0.0.
- `https://acryl.dev/v1/plugins` validates against `CatalogProviderPage`
  v1.0.0, including a well-formed `page` object.
- In ACRYL Desktop with the `community-market` provider enabled, the ACRYL
  source is listed by default and its plugins (starting with
  `cordis-plugin-graph`) are browsable and installable end to end.
- A plain DSH Desktop install can add the ACRYL market client from npm and
  reach the same catalog, or add the manifest URL to a compatible client.
- The acryl.dev repo has a CI check that fails if either served document
  drifts from the schema.
- The market client fails soft on a DSH version mismatch instead of breaking
  the plugin host.
