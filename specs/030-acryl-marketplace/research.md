# Research: ACRYL Marketplace

Facts established while diagnosing the `dsh-market` recovery-screen incident
(2026-09-10). Verified against the tree at DSH `0.1.5-alpha.1`.

## The market-client landscape

| Client | Package | Origin | Notes |
| --- | --- | --- | --- |
| Community market | `dsh-community-market` | this repo, `private: true` | Our provider. Optional, disabled by default. Enabled via Settings -> Desktop -> Plugin market -> `community-market`. |
| DSH market | `dshmarket@1.17.1` | third-party, `zhu1090093659/dsh-web`, from deepseek1024.com | Bundled as an `acryl-desktop` dependency so the `dsh-market` provider option can resolve it. |

`DESKTOP_MARKET_IDENTITIES` (`acryl-desktop/src/desktop-market.ts`):
- community: provider `community-market`, rowId `community-market`, package `dsh-community-market`
- dshMarket: provider `dsh-market`, rowId `dsh-market`, package `dshmarket`

Selection persists to
`<userData>/desktop-market/state.json` -> `{version, requested, legacyDefaulted}`
(`readDesktopMarketStateForUserData` -> `desktopMarketStatePath`).

## Why `dsh-market` bricks the profile on 0.1.5-alpha.1

`dshmarket/lib/settings.js:35`:
```js
import { installSettingsSection, settingsNamespace } from '@deepseek-ai/dsh-settings';
```
- `@deepseek-ai/dsh-settings@0.1.1-rc.2` exports both.
- `@deepseek-ai/dsh-settings@0.1.5-alpha.1` exports only
  `SettingsConflictError, SettingsProvider, default, redactSecrets`.
  `installSettingsSection` and `settingsNamespace` were removed.
- `dshmarket` declares `@deepseek-ai/dsh-settings: ^0.1.0-rc.7` and pnpm
  resolves it to the `0.1.5-alpha.1` copy -> ESM `SyntaxError` at module
  instantiation -> `cordis-plugin-loader` rethrows -> whole plugin tree fails
  -> ACRYL Recovery screen (`Failure stage: Plugin Host startup`).

`prepareDesktopProfile` already degrades gracefully in principle:
`validateMarketPackage` (community) and `validateDshMarketBundlePatches`
(dsh-market) set `marketFailure`, keep `effectiveMarket = 'disabled'`, and
surface a notice instead of inserting a broken provider. But those guards
only check package resolution and patch shape - never that the module graph
actually imports. So an upstream API break passes the guard and detonates in
the loader. Fix: ESM import-smoke the provider entry before committing it.

`dsh-community-market` is clean on this axis - it imports `dsh-settings`
type-only (`import type { SettingsScope }`), is pinned to `0.1.5-alpha.1`, and
`verify-loader-boot.mjs` explicitly asserts `include:community-market`
activates through its bare package name.

## UX defect

Settings -> Desktop writes the market selection and relaunches immediately,
no confirmation, no "this restarts ACRYL" warning. Once the resulting profile
fails you land in Recovery with no in-app way back to `disabled` except
switching profiles or editing the state file. On reopen the left panel shows
the plugins as "activated" even though the host failed.

## The catalog-source contract (already in-repo)

`dsh-community-market/src/contracts/generated/`:

- `catalog-source.ts` - `CatalogSourceManifest` v1.0.0:
  `manifestVersion, providerId, name, description?, homepage?,
  attribution{name,url,notice?}, transport{kind:'https-json',endpoint,method:'GET'},
  query{supported[], defaultLimit, maxLimit, sorts}`.
  `supported` values: `q | category | capability | cursor | limit | sort | locale`.
  Endpoint: absolute HTTPS:443, no query/fragment, same origin as the
  manifest, path ends `/v1/plugins`.
- `catalog-provider-page.ts` - `CatalogProviderPage` v1.0.0:
  `schemaVersion:'1.0.0', generatedAt?, revision?, items[<=100], page`.
  `items[]` require `id, name, displayName, summary` and at least one of
  `repository` / `package`; optional `homepage, latestVersion, license,
  categories[<=32], keywords[<=64], publisher, media, capabilities[<=64],
  compatibility, updatedAt`.

Adapters: `standard-http.ts` (generic HTTPS), `dsh-1024store.ts` (built-in
deepseek1024.com cooperating source), `dshfind.ts`. Trust root enforced by
`assertStandardSourceTrustRoot(manifestUrl, manifestFinalUrl, endpoint)`:
all three must share one origin.

Managed install (`install/service.ts`): verifies npm identity, canonical
repository, integrity, no lifecycle scripts, DSH bundle evidence.

## acryl.dev today

`acryldev/acryldev.github.io` (GitHub Pages, CNAME `acryl.dev`):
- `public/v1/plugins` and `dist/v1/plugins` already exist, `CatalogProviderPage`
  shape, `schemaVersion: "1.0.0"`, `items[]` populated (first entry
  `cordis-plugin-graph@0.2.0`). Currently missing the required `page` object.
- Generated by `scripts/sync-acryl-catalog.mjs`: npm keyword `acryl-package`
  discovery merged with `src/data/maintained-acryl-packages.json`
  (`new Map([...maintained, ...discovered])`, discovered wins).
- `src/lib/catalog.mjs` `inspectAcrylManifest` validates a package's
  `manifest.acryl` block (`{schemaVersion:1, artifacts:{plugins:[...]}}`).
- No `CatalogSourceManifest` published. GitHub Pages is static: query params
  (`q`, `category`, `cursor`, `limit`) cannot be honored server-side without
  moving to an edge function or pre-sharding.

`acryldev/store` (`dsh-store` / `store`) is the broader DSH plugin directory
(separate from acryl.dev's first-party list); aggregates npm keyword,
github-topic, 1024store, awesome-dsh, composio sources.
