Spec 055 · design, not built

Publish, Share, Git sync and History, the Lovable way

Every change becomes a version automatically. Connect GitHub once and the app syncs by itself. One Publish button covers the web, the desktop installers and the Blends store. Share is for people. Below, every state each part can be in, plus how the WebBoxes deploy that is waiting looks in each case.

Modeled on Lovable (History with Bookmarks, Restore as a new step, two-way GitHub sync) and Base44. Built on what the frame already has: the Git tab's push and pull with a confirmed plan (RemoteSync.tsx), GitHub's device-code connect (ShareChooser.tsx), the secret check, and Share with team (app-team-release.ts).

What changes

History replaces Versions

Automatic versions after each agent turn and after your own edits. A star bookmarks one. Restore brings one back as a new version. Save point button and its name field

GitHub sync replaces Share to GitHub

Connect once in Settings > GitHub. It creates a private repository and keeps it in sync both ways. The secret check runs before every sync. The plan form for each push

Publish new, top bar

One dialog with three tabs: Web, Desktop app and Blends store. "Share with team" becomes Publish > Desktop app.

Share new, top bar

For people only: copy the app's link, invite someone on GitHub, or download the code as a ZIP.
