Why there and not in the Lifecycle tab: it is the page every DSH user already knows, any app built on DSH has it (a Blend made with acryl new too, not only the IDE), and DSH made these three spots for exactly this. The Lifecycle tab stays the engineer's view (rows, mounted state, reload) with no second set of buttons. Limits: DSH's list cards have no spot for extra tags, so "update available" shows on the plugin's page, not on its card, until DSH adds one. To check live: that a plugin the agent wrote in your project shows in Installed like a pulled one.

B. Where a comment goes

The problem you raised on 2026-10-13 ("passed to currently running node Pty tab currently active") was built with a hidden rule, and the other comment paths each use a different one. With several agents and terminals open, you cannot tell where a comment will land.

Where you commentWhere it goes todayWhat goes wrong
"+" beside a line in a fileThe terminal you typed in last, in any worktree (comment-target.ts)problem 1 It can be a plain zsh, the dock's test terminal, or an agent on another branch. You learn the target only after it was sent.
A line in a Diff tabThe DSH chat currently shown (sendToCurrentSession)problem 2 If Claude Code in a terminal works on that branch, it never hears about it.
Pick an elementThe clipboardproblem 3 You paste it by hand, and nothing records it.
HTML prototype (Lavish)Not built inside ACRYLplan Needs the same answer.

Your design (2026-10-18): comments are kept, and you choose where they go

Comment no longer sends anything by itself. It leaves a bubble under the line. From the bubble, or from the new Comments page in the right panel, you copy a comment or send it to one of the open terminals or agents.
