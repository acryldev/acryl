What each tile really does today

Tile or paneData behind itGap versus a working ADE
chatrealUpstream conversation, bound to a workspace (its worktree). A blank chat with no workspace cannot send.
ptyreal run from ChecksHost PTY started in the worktree folder. Tabs are not restored after a restart.
diffreal gitUnified diff with single-line comments to the agent. Multi-line ranges not built. The old "two pasted texts" mode remains for a plain New Diff tab.
filereal editor addedFiles tab opens a real file in a CodeMirror editor: syntax highlighting for the major languages, in-file search, save with Cmd or Ctrl+S, a dot while unsaved, drafts kept when you switch tabs, and a warning if the file changed on disk. The plain New File tab is still a scratch box.
browserpartialAddress bar plus frame. No design or annotate mode.
kanban, docshell onlyLocal cards and pasted text. Not tied to sessions or to real spec files.
Surface gap: everything in Part 1 runs on Desktop only today. The decision (2026-09-26) is one implementation shared by Web and Desktop, so making Web run it is the next slice (spec 040, Phase 7) before more features.

Tab types and what a branch owns

The canvas is the tabs pane. Chat is simply one tab type: the conversation DSH and ACRYL already have. Everything else is another tab type opened from +. Which types are offered is a setting; the default is all of them, and a developer can pick a minimal set.

Settings > Workspace > Tab types

Preset: All (default)Preset: Minimal - Chat, Agent, Terminal

The checkboxes above are a local preview and do not save. Tab types come from plugins, so a type only appears here if its plugin is loaded.

Model change this implies

WorkspaceState today holds one flat list of tiles for the whole shell. The new model is project > branch or worktree > tab group: each branch owns its own ordered tabs and active tab, and selecting a branch swaps the canvas to that group. The terminal dock follows the same rule. Tab groups must persist across restarts.

Example

On master of the website: a Browser tab, Claude Code and Codex. Click feat/meta-chat: the canvas re-renders with its own MD doc, Qwen and Pi. Click back: the first group returns exactly as left.

Architecture: every feature is a plugin you can turn off

Each tab type, the rail, the panel, the dock, the top bar and the status bar is its own Cordis plugin with its own Loader row. Turning one off is a profile patch (disabled: true), the same mechanism acryl-development-canvas already documents. acryl-workspace stays small: it owns the shell layout, per-worktree tab groups, and one service that tab-type plugins register into. Names below are proposed; per repo rule the Loader row id equals the package name.

PluginProvidesConsumes (inject)When turned off
acryl-workspaceShell layout, tab groups per worktree, the workspaceTabs registry serviceslotsAdvanced shell falls back to upstream's default main area
acryl-tab-chatTab type chat (the existing DSH conversation, incl. Trajectory)workspaceTabsNo chat tab offered
acryl-tab-agentTab type agent (Claude, Codex, OpenCode, Pi, Qwen...)workspaceTabs, acryl-controlAgents are not launchable from +
acryl-tab-terminalTab type terminal, the PTY Host route, the dock's session typeworkspaceTabs, webServerNo terminals, and the dock has nothing to host
acryl-tab-browser, -file, -md, -diff, -kanban, -compare, -prototypeOne tab type each. -prototype is the Lavish-style annotate and feedback loopworkspaceTabs; diff and compare also acryl-gitThat type disappears from +; existing tabs of it show a "plugin off" placeholder
acryl-gitWorktree, status and diff Host servicewebServerRail loses branch data, panel loses Changes, diff and compare go PENDING
acryl-workspace-projects, -panel, -dock, -topbar, -statusbarThe five chrome areasworkspaceTabs, acryl-git (optional)That area is not rendered; the rest of the shell still works

Consequence to design for: a consumer whose provider is missing is PENDING, not broken, and must reactivate when the provider returns. That is exactly what the Cordis lifecycle gives us, so tab-type plugins hard-inject workspaceTabs and treat acryl-git as optional.

Decisions (made 2026-09-24)

Resolved through this page. They are now the working baseline for spec 040 Scope A.

#QuestionDecisionWhat it means
1Canvas layoutTabs plus one optional splitKeep WorkspaceState close to today's shape; add a single split so an agent can sit next to its diff.
2First build sliceReal diff tile with line comments sent to the agentNeeds the tab-type registry, an acryl-git Host service, then acryl-tab-diff. Comments become room events.
3Switching branchKeep other branches' tabs running in the backgroundAgents and terminals in an unselected branch keep working; the rail dot stays live. Process count needs a cap and a visible indicator.
4Code basisEvolve acryl-workspace in placeSplit each tile into its own plugin, move to per-worktree tab groups, extract the PTY as it is into acryl-tab-terminal.
5SurfacesOne shared implementation for Web and Desktop decided 2026-09-26Composed once through coding-capabilities.ts (surfaces: [desktop, web]), shared shell package, typed adapters only for native bits (folder chooser, drag-drop), and a parity gate. Today it is Desktop-only, which is a defect against this decision. Spec 041 Agent Control follows the same rule.
