bltuxui: a prompt-first app builder

A redraw of an established AI app builder from 20 screenshots, 14 accessibility captures and 2 documents. Neutral styling, ACRYL's design tokens, no logos or brand copy. The source product is written as bltuxui throughout.

The UX model

bltuxui is a prompt-first AI app builder. The public start screen is one composer with four typed project modes (website, slides, app, prototype) and three import paths; signing in leads to a home with the same composer, a project sidebar and recent work. The builder itself is a three-part workspace: a chat column on the left where the agent's turns, file chips, an action count and a plan checklist live; a preview in the middle with Preview / Code / Database tabs, an address bar and a device toggle; and a top bar that separates project switching, history, GitHub, Upgrade, Share and Publish. Pricing is token-based, with a hard upgrade dialog when the allowance runs out. The marketing site is a conventional product site: a prompt hero, a token pricing table, a template gallery, use-case landing pages built from one template, and trust pages for enterprise and security.

Take for ACRYL / Do not take / Why

TakeWhy
One composer with four typed project modes on the first screenThe mode is decided before the agent starts; four buttons are cheaper than a setup wizard, and the prompt stays the centre.
"N actions taken" folded per turnA long agent turn stays one line in the transcript, but its work is still inspectable.
A plan checklist with completed steps struck throughThe user can see the intended sequence before the build and follow progress without opening a log.
Preview / Code / Database tabs on one canvasOne surface answers three questions (does it run, what is the code, what is the data) without changing screens.
Share and Publish as separate top-bar actionsA private link and a public release are different promises; ACRYL spec 055 already separates them.
Cost shown at the point of promptingThe mode picker rates speed, intelligence and token cost; the pricing page repeats the allowance.
A template gallery with open and preview actionsStarting from a working example is faster than a blank prompt; the prompt fallback covers the rest.
Do not takeWhy
A two-column editor with no right-hand review panelThe visible editor has chat and preview only. ACRYL's frame already gives changes, review and files a right panel; do not drop it to match this layout.
Locked modes and a mid-build paywallThe token limit interrupts a running project with a modal. Show cost before the turn and offer a way to finish the current one.
"Actions taken" as the only historyThe count is a summary, not a restorable timeline. ACRYL spec 055's History is the richer model.
Token-only plan pricingThe source sells AI tokens. ACRYL also sells hosting, desktop builds and publishing, so the pricing unit must not be copied blindly.
Marketing copy and social proof inside the builderIt belongs on the site. The editor should stay a workspace.
A referral card in the empty previewIt competes with the first build; keep growth outside the canvas.
Hiding the file tree behind tabsThe default state shows no file structure; ACRYL's Files/Changes should stay one visible action away.

What the screens do not show

  • Sign-in and account creation; the editor is behind auth.
  • File tree, code editor content and database content; the tabs are visible, the panes are not.
  • Share, Publish, GitHub, Upgrade and History dialogs; only the top-bar entries are visible.
  • Any version list or restore flow; only the History icon is visible.
  • Settings, team management, collaboration, comments or notifications.
  • The product's own phone-width layout.
  • What changes between agent modes; only the ratings and locks are visible.
  • Whether a prompt before sign-in creates a project or is kept after auth.
  • The pricing FAQ answers; the questions are visible, the answers are collapsed.
  • Whether "actions taken" can be expanded into individual edits; the control is a collapsed row.
  • Usage meters, token balances or a soft-limit warning before the hard modal.
  • The live behaviour of the marketing forms; they are captured as page structure only.
